<analysis>**original_problem_statement:**
The user requested a subscription-based food delivery application named EATWEL. The project consists of three main components: an Admin Web Panel, a Customer Mobile App, and a Delivery Boy Mobile App.

**PRODUCT REQUIREMENTS:**
*   **App Type**: Subscription-based food delivery for a single restaurant/cloud kitchen.
*   **User Roles**: Admin, Customer, and Delivery Boy with separate, distinct login flows.
*   **Authentication**:
    *   Admin/Delivery Boy: Login with an ID and Password set by the Admin.
    *   Customer: Self-register with a custom Login ID, Name, Mobile, and Password.
*   **Admin Panel (Web)**: Manage Delivery Boys, Combos (dish groups), Subscription Plans, Zones (via Google Maps polygon drawing), Orders, and promotional Banners. Includes a dashboard for key metrics and a settings page for app configuration.
*   **Core Logic**: An Order Generation Engine automatically creates daily orders based on active subscriptions and meal timings (Breakfast, Lunch, Dinner).
*   **Customer App**: Register/Login, view/buy plans, select delivery location via map, track order status, pause/resume subscriptions, and change password.
*   **Delivery Boy App**: Login, view assigned orders, update order status (Out for Delivery, Delivered), and view customer route on a map. Features a privacy rule where customer contact details are hidden until an order is Out for Delivery.
*   **Payment**: An online payment gateway integration is required but not yet implemented.

**User's preferred language**: English
